Message Queue — Definition

Ek Message Queue ek asynchronous communication mechanism hai jisme:

  • Producer — message bhejta hai queue mein (sender)
  • Queue — messages store karta hai jab tak consumer ready na ho
  • Consumer — queue se messages leta hai aur process karta hai

Producer aur Consumer ek doosre ke baare mein kuch nahi jaante — yahi decoupling hai.

🎯 Real-World Use Cases
  • Email/SMS notifications — user signup pe welcome email
  • Order processing — e-commerce mein payment → inventory → shipping
  • Image processing — upload ke baad thumbnail generation
  • Log aggregation — distributed services ke logs centralize karna
  • Event sourcing — microservices events broadcast karna
  • Rate limiting — third-party API calls control karna

DIAGRAM 2 RabbitMQ Full Architecture — Producer → Exchange → Queue → Consumer
📤 Producer

Application jo messages publish karta hai RabbitMQ ko. Producer ko queue ka pata nahi hota — woh sirf Exchange ko message bhejta hai ek routing key ke saath.

🔀 Exchange

Messages receive karta hai producers se aur decide karta hai ki message kaunsi queue(s) mein jaayega. Routing rules exchange type par depend karte hain.

📦 Queue

Message store karne ki jagah. FIFO order. Multiple consumers ek queue se le sakte hain. Durable queue server restart ke baad bhi survive karta hai.

🔗 Binding

Exchange aur Queue ke beech ka link. Binding key define karta hai ki kaunsa message kaunsi queue mein jaayega. Ye routing table ki tarah hai.

📥 Consumer

Queue se messages consume karta hai. Message process karne ke baad ACK (acknowledgement) bhejta hai. Bina ACK ke message queue mein wapas aa jaata hai.

🌐 Virtual Host

Logical isolation — ek RabbitMQ server pe multiple isolated environments. Alag-alag teams ya applications ke liye use hota hai. Default vhost / hota hai.

💡 KEY INSIGHT: Connection vs Channel

Connection = TCP connection to RabbitMQ (expensive — ek application ke liye ek). Channel = Lightweight virtual connection INSIDE a TCP connection (multiple per connection — har thread ke liye alag channel banao). Ye AMQP ka important optimization hai.

Phase 1 · Section 3
Exchange Types — Routing Ki Duniya
4 exchange types hain — in sab ka use case alag hai. FAANG interviews mein ye zaroor poochha jaata hai.
1. Direct Exchange

Routing key exact match hoti hai binding key se. Ek specific queue ko message bheja jaata hai. Simple 1-to-1 routing.

routing_key == binding_key

Use: Task queues, specific worker assignment, RPC pattern

2. Fanout Exchange

Routing key IGNORE karta hai. Message sabhi bound queues mein bheja jaata hai. Pure broadcast.

routing_key ignored — all queues get it

Use: Notifications, cache invalidation, event broadcasting

3. Topic Exchange

Routing key pattern match karta hai * (one word) aur # (zero or more words) wildcards se. Most flexible.

logs.* matches logs.error, logs.info

Use: Microservices events, complex routing, logs by severity

4. Headers Exchange

Routing key ki jagah message headers use karta hai matching ke liye. x-match: all ya any. Least used.

match on headers instead of routing key

Use: Complex attribute-based routing, multi-criteria filtering

NODE.JS producer.js — Message publish karna 
const amqp = require('amqplib');

async function sendMessage() {
  // Step 1: Connection establish karo
  const connection = await amqp.connect('amqp://admin:admin123@localhost:5672');

  // Step 2: Channel banao (lightweight, connection ke andar)
  const channel = await connection.createChannel();

  // Step 3: Queue declare karo (idempotent — agar exist kare toh kuch nahi hoga)
  const queueName = 'task_queue';
  await channel.assertQueue(queueName, {
    durable: true  // Server restart ke baad bhi queue survive karegi
  });

  // Step 4: Message publish karo
  const message = { userId: 123, email: 'rajesh@gmail.com', template: 'welcome' };
  const msgBuffer = Buffer.from(JSON.stringify(message));

  channel.sendToQueue(queueName, msgBuffer, {
    persistent: true   // Message disk pe save hoga (not lost on crash)
  });

  console.log('✅ Message sent:', message);

  // Step 5: Cleanup (production mein connection reuse karo)
  setTimeout(() => {
    connection.close();
    process.exit(0);
  }, 500);
}

sendMessage().catch(console.error);
NODE.JS consumer.js — Messages consume karna with proper ACK 
const amqp = require('amqplib');

async function startConsumer() {
  const connection = await amqp.connect('amqp://admin:admin123@localhost:5672');
  const channel   = await connection.createChannel();

  const queueName = 'task_queue';
  await channel.assertQueue(queueName, { durable: true });

  // IMPORTANT: Ek baar mein sirf 1 message process karo
  // Jab tak ACK na aaye, next message mat lo
  channel.prefetch(1);

  console.log('🐰 Waiting for messages...');

  channel.consume(queueName, async (msg) => {
    if (msg === null) return; // Consumer cancelled

    const data = JSON.parse(msg.content.toString());
    console.log('📨 Received:', data);

    try {
      // Actual kaam karo (email send, DB write, etc.)
      await processMessage(data);

      // ✅ SUCCESS: RabbitMQ ko batao message process ho gaya — delete karo
      channel.ack(msg);
    } catch (err) {
      console.error('❌ Processing failed:', err);

      // ❌ FAILURE: Message wapas queue mein daalo (requeue: true)
      // requeue: false → message dead-letter queue mein jaayega
      channel.nack(msg, false, true);
    }
  }, {
    noAck: false  // Manual ACK mode (ALWAYS use this in production!)
  });
}

async function processMessage(data) {
  // Simulate async work (email send, API call, etc.)
  await new Promise(resolve => setTimeout(resolve, 1000));
  console.log(`📧 Email sent to ${data.email}`);
}

startConsumer().catch(console.error);
⚠️ CRITICAL: noAck: false ALWAYS in Production

noAck: true matlab message consume hote hi delete ho jaata hai — chahe processing fail ho. Production mein always noAck: false use karo aur manually channel.ack(msg) call karo success pe aur channel.nack(msg) failure pe.

NODE.JS rpc-client.js — Request bhejo aur response lo 
const amqp = require('amqplib');
const { v4: uuidv4 } = require('uuid');

class RPCClient {
  constructor() {
    this.connection = null;
    this.channel    = null;
    this.replyQueue = null;
    this.pending    = new Map(); // correlationId → { resolve, reject }
  }

  async connect() {
    this.connection = await amqp.connect('amqp://localhost');
    this.channel    = await this.connection.createChannel();

    // Temporary exclusive reply queue (auto-deleted when client disconnects)
    const q = await this.channel.assertQueue('', {
      exclusive: true,   // Only this connection can use it
      autoDelete: true   // Delete when connection closes
    });
    this.replyQueue = q.queue; // amq.gen-XYZ (random name)

    // Listen for replies on this temp queue
    this.channel.consume(this.replyQueue, (msg) => {
      const corrId = msg.properties.correlationId;
      const handler = this.pending.get(corrId);
      if (handler) {
        const result = JSON.parse(msg.content.toString());
        handler.resolve(result); // Promise resolve karo !
        this.pending.delete(corrId);
      }
    }, { noAck: true });
  }

  call(rpcQueue, payload, timeout = 10000) {
    return new Promise((resolve, reject) => {
      const correlationId = uuidv4();

      // Timeout handling
      const timer = setTimeout(() => {
        this.pending.delete(correlationId);
        reject(new Error('RPC timeout'));
      }, timeout);

      this.pending.set(correlationId, {
        resolve: (val) => { clearTimeout(timer); resolve(val); },
        reject
      });

      this.channel.sendToQueue(rpcQueue, Buffer.from(JSON.stringify(payload)), {
        correlationId,                   // "This is my ID"
        replyTo: this.replyQueue         // "Reply here"
      });
    });
  }
}

// Usage:
const client = new RPCClient();
await client.connect();
const result = await client.call('math.add', { a: 5, b: 3 });
console.log('Result:', result); // { result: 8 }

DIAGRAM 7 Dead Letter Queue (DLQ) — Message Lifecycle on Failure
NODE.JS Dead Letter Queue Setup + Exponential Backoff Retry 
const amqp = require('amqplib');

async function setupQueuesWithDLQ(channel) {
  // Step 1: Dead Letter Exchange declare karo
  await channel.assertExchange('dlx', 'direct', { durable: true });

  // Step 2: Dead Letter Queue declare karo
  await channel.assertQueue('dead_letter_queue', {
    durable: true
  });
  await channel.bindQueue('dead_letter_queue', 'dlx', 'failed');

  // Step 3: Main Queue with DLQ config
  await channel.assertQueue('email_queue', {
    durable: true,
    arguments: {
      'x-dead-letter-exchange': 'dlx',          // Failed msgs yahan jaayenge
      'x-dead-letter-routing-key': 'failed',    // Routing key for DLX
      'x-message-ttl': 300000,                   // 5 min baad expire → DLQ
      'x-max-length': 10000                       // Queue full → oldest → DLQ
    }
  });
}

// ── CONSUMER with Exponential Backoff Retry ──────────────────
async function consumeWithRetry(channel, msg, handler) {
  const data       = JSON.parse(msg.content.toString());
  const retryCount = (msg.properties.headers?.['x-retry-count'] || 0);
  const MAX_RETRIES = 3;

  try {
    await handler(data);
    channel.ack(msg);  // ✅ Success

  } catch (err) {
    console.error(`❌ Attempt ${retryCount + 1} failed:`, err.message);

    if (retryCount < MAX_RETRIES) {
      // NACK without requeue — message goes to DLQ (or retry delay queue)
      channel.nack(msg, false, false);

      // Exponential backoff: 2^retry * 1000ms (1s, 2s, 4s, 8s...)
      const delay = Math.pow(2, retryCount) * 1000;
      console.log(`🔄 Retrying in ${delay}ms...`);

      // Re-publish with incremented retry count after delay
      setTimeout(() => {
        channel.sendToQueue('email_queue', msg.content, {
          persistent: true,
          headers: { 'x-retry-count': retryCount + 1 }
        });
      }, delay);

    } else {
      // Max retries exhausted → DLQ mein jaayega
      console.error('💀 Max retries exhausted — moving to DLQ');
      channel.nack(msg, false, false); // DLX handle karega

      // Alert send karo!
      await sendAlert(`Message failed after ${MAX_RETRIES} retries`, data);
    }
  }
}
🎯 FAANG Interview: DLQ Questions
  • Q: "Payment message fail ho gayi — kya karoge?" → DLQ setup karo, retry 3 times with exponential backoff, alert send karo, manual investigation allow karo
  • Q: "DLQ vs Retry Queue difference?" → DLQ = final destination after max retries. Retry queue = delay ke saath same queue mein wapas
  • Q: "At-least-once delivery kaise guarantee karte ho?" → manual ACK, durable queues + persistent messages, idempotent consumers
  • Q: "Exactly-once delivery possible hai?" → RabbitMQ mein not natively. Idempotency key + DB check se achieve karo (consumer side)

Production-Grade Connection Manager

NODE.JS rabbitmq-manager.js — Production connection pool with reconnect 
const amqp = require('amqplib');
const EventEmitter = require('events');

class RabbitMQManager extends EventEmitter {
  constructor(url, options = {}) {
    super();
    this.url          = url;
    this.options      = options;
    this.connection   = null;
    this.channels     = new Map(); // name → channel
    this.reconnecting = false;
    this.maxRetries   = options.maxRetries || 10;
    this.retryDelay   = options.retryDelay || 5000;
  }

  async connect() {
    try {
      this.connection = await amqp.connect(this.url);
      console.log('🐰 RabbitMQ connected!');
      this.emit('connected');

      // Connection error handling
      this.connection.on('error', (err) => {
        console.error('Connection error:', err.message);
        this._reconnect();
      });

      this.connection.on('close', () => {
        console.warn('🔌 Connection closed — reconnecting...');
        this._reconnect();
      });

    } catch (err) {
      console.error('Failed to connect:', err.message);
      await this._reconnect();
    }
  }

  async _reconnect(attempt = 0) {
    if (this.reconnecting) return;
    if (attempt >= this.maxRetries) {
      console.error('💀 Max reconnection attempts reached');
      this.emit('failed');
      return;
    }

    this.reconnecting = true;
    const delay = Math.min(this.retryDelay * Math.pow(2, attempt), 60000);
    console.log(`🔄 Reconnecting in ${delay}ms (attempt ${attempt + 1})`);

    await new Promise(r => setTimeout(r, delay));
    this.reconnecting = false;
    this.channels.clear(); // Old channels invalid hain
    await this.connect();
  }

  async getChannel(name = 'default') {
    if (this.channels.has(name)) return this.channels.get(name);

    const channel = await this.connection.createChannel();
    channel.on('error', () => this.channels.delete(name));
    channel.on('close', () => this.channels.delete(name));

    this.channels.set(name, channel);
    return channel;
  }

  async publish(exchange, routingKey, message, options = {}) {
    const channel = await this.getChannel('publisher');
    const content = Buffer.from(JSON.stringify(message));
    return channel.publish(exchange, routingKey, content, {
      persistent: true,
      contentType: 'application/json',
      timestamp: Date.now(),
      ...options
    });
  }

  async subscribe(queue, handler, prefetch = 10) {
    const channel = await this.getChannel(`consumer_${queue}`);
    await channel.prefetch(prefetch);

    channel.consume(queue, async (msg) => {
      if (!msg) return;
      try {
        const data = JSON.parse(msg.content.toString());
        await handler(data, msg);
        channel.ack(msg);
      } catch (err) {
        channel.nack(msg, false, false); // → DLQ
      }
    }, { noAck: false });
  }
}

// Usage:
const mq = new RabbitMQManager('amqp://admin:admin123@localhost');
await mq.connect();
await mq.publish('notifications', 'email.welcome', { userId: 123 });
await mq.subscribe('email_queue', async (data) => {
  console.log('Processing:', data);
});

🎯 FAANG System Design — RabbitMQ Questions & Answers
  • Q: "RabbitMQ vs Kafka — kab kya use karoge?"
    → RabbitMQ: complex routing logic, task queues, RPC pattern, per-message acknowledgement, varied message sizes. Kafka: event streaming, replay, ordered partition-level processing, millions of events/sec, audit log.
  • Q: "Messages guaranteed delivery kaise karoge?"
    → Durable exchange + durable queue + persistent messages + manual ACK. In teen ko combination use karo. Publisher confirms enable karo for producer-side guarantee.
  • Q: "1 million messages per day handle kaise karoge?"
    → Multiple consumers (horizontal scale), prefetch tuning (10-50 per consumer), quorum queues for HA, partitioned topic exchanges, lazy queues for large backlogs.
  • Q: "Single node RabbitMQ production mein acceptable hai?"
    → NEVER. Minimum 3-node quorum cluster. HAProxy for client-side load balancing. Each node in different availability zone.
  • Q: "Message ordering guarantee chahiye — kaise karoge?"
    → Single queue + single consumer = guaranteed order. Multiple consumers = no order guarantee. Agar order chahiye with scale: consistent hashing by entity_id to specific queue.
  • Q: "Idempotent consumer kaise banate hain?"
    → Message mein unique message_id include karo. Consumer DB mein check karo "already processed?" before executing. Redis SET NX for fast deduplication check.
